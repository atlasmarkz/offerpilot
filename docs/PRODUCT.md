# 产品与收费规划

本文记录两种使用方式、订阅内容建议、成本与合规的注意事项。**这是规划，不是法律意见；收费上线前请自己核实平台规则与法规。**

## 两种使用方式

| | A. 自己部署 | B. 托管版（你的网站） |
|---|---|---|
| 谁出模型费用 | 用户自己（填自己的 Base URL / API Key / 模型名） | 站点提供 MiniMax，按额度计费；用户也可以自带模型，免费且不扣额度 |
| 账号 | 不需要 | 邮箱验证码登录 |
| 计费 | 关闭（不设 `BILLING_ENABLED`） | `BILLING_ENABLED=1` + `SUPABASE_SERVICE_KEY` |
| 数据 | 都在自己手里 | 云端只存：画像、已选岗位、**最新一份结构化简历**、额度流水 |

同一套代码，靠环境变量切换。

## 额度规则（已实现）

- 额度**所有大模型功能共用**：简历解析、修改建议各扣 1 次（`apps/web/lib/billing/billing.ts` 的 `UNIT_COST`，调价只改这里）。
- 扣减顺序：先订阅额度，再次数包。订阅每期 100 次，到期不结转；次数包不过期。
- 先读文件再扣额度：读不出文字的文件不扣；模型调用失败自动退还；模型没给出有效建议也退还。
- 扣减、退还、发放只能由服务端用 `service_role` 调数据库函数完成，用户的令牌调用会被拒绝，用户只能**读**自己的余额。
- 用户自带模型：不要求登录、不扣额度。

### 管理员发放额度（支付接入前用它代替收款）

```bash
npm run billing -w @offerpilot/crawler -- grant 用户邮箱 20          # 发 20 次
npm run billing -w @offerpilot/crawler -- subscribe 用户邮箱 30 100  # 开通 30 天、100 次/期
npm run billing -w @offerpilot/crawler -- show 用户邮箱              # 查看余额与最近用量
```

对方需要先登录过一次。支付接入后，支付回调会调用同样的 `grant_credits` / `set_subscription` 函数。

## 简历数据的原则（已实现）

- 只保存**解析后的结构化数据**，每人一份，每次保存整份覆盖，云端永远是最新的。
- **不保存**原始 PDF/Word，也不保存简历全文；上传文件只在内存里处理。
- 联系方式（姓名、电话、邮箱、链接）由用户自己在编辑器里填，**不会发给大模型**。
- 用户随时可以删除账号，所有云端数据（含简历、额度记录）一并删除。

## 定价思路

- 先估成本：一次解析是几千字输入加一两千字输出，按 MiniMax 当前单价核算（请到其价格页确认），通常是几分钱量级。
- 定价留余量：模型成本 + 支付手续费 + 重试 + 免费用户消耗 + 客服时间。
- 建议先上线观察一个月的真实调用量和成本，再定价。
- 防滥用：单次文件大小上限（5MB，已有）、失败不扣次数（已有）、按 IP 的验证码限流（已有）。

## 收费前的现实门槛（不是代码能解决的）

1. **支付资质**：微信支付、支付宝商户都要求营业执照（个体工商户即可）。你已选择办个体户后接入。
2. **网站备案**：网站类收款通常要求已 ICP 备案的域名；备案要走国内云服务商，服务器一般放国内。这意味着收费版可能要从 Vercel 迁到国内云服务器（用 Docker 部署）。
3. **生成式 AI 合规**：向境内公众提供基于大模型的服务有登记备案等要求，用已备案的模型会简单一些，但服务方自身是否需要登记，请向主管部门或专业人士确认。
4. **个人信息**：简历属于敏感度较高的个人信息，需要明确同意、最小化存储、删除途径（隐私说明页已写明）。
5. **税务与发票**：办理个体户后一并处理。
